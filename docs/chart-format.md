# INTERVAL 谱面格式 v4（兼容 v1 / v2 / v3）

v4 在 v3 的每条线中增加可选 `events`，分别包含 `x`、`alpha`、`speed` 三栏。每个区间为 `{ "start": 2, "end": 6, "from": 1, "to": 2, "ease": "sine_in_out" }`；**导出谱面使用秒，工程使用拍**。`start < end`，同栏按起点排序且不重叠，每栏最多 256 段。

位置 / 透明度值为 0–1，速度为 0–8。缓动支持 `linear`、`sine_in_out`、`sine_in`、`sine_out`、`smooth`、`hold`。`hold` 在区间内保持 `from`，到终点变为 `to`；区间之外保持上一段终值。相邻区间的边界以后一段起值为准。

`frames` 仍保留。未提供事件栏时，位置与透明度按旧关键帧计算，速度为 1；提供某一事件栏时，该栏覆盖旧关键帧的对应属性。初始位置 / 透明度取首个旧帧，初始速度为 1。显式空事件栏保持初始值。新线默认首帧 `{ "time": 0, "x": 0.5, "alpha": 0, "ease": "linear" }`，无音符。

可变流速使用积分距离 `∫当前时间→音符时间 speed(t) dt` 绘制，Tap / Hold 各点横坐标仍取相应绝对到达时间的轨迹位置。音乐、判定窗口、音符时间均不随流速改变。Android 0.9.0 开始支持 v4，旧版会提示升级，避免默默忽略速度事件。

下方为仍受支持的 v3 基础示例。

时间单位为秒，所有坐标为归一化坐标。`notes` 按时间升序排列。下例只展示格式，内置完整谱面请查看 `app/src/main/assets/demo.json`。

```json
{
  "version": 3,
  "title": "Example",
  "artist": "Artist",
  "difficulty": "EZ",
  "bpm": 120,
  "audio": "example.ogg",
  "duration": 60,
  "offset": 0,
  "approachTime": 2.2,
  "editor": {"meter": 4, "division": 4, "gridUnit": "beat"},
  "sections": [
    {"start": 0, "end": 20, "label": "全域", "rects": [[0, 0, 1, 1]]},
    {"start": 20, "end": 40, "label": "下半区", "rects": [[0, 0.5, 1, 1]]},
    {"start": 40, "end": 63, "label": "双区", "rects": [[0, 0, 0.45, 1], [0.55, 0, 1, 1]]}
  ],
  "lines": [
    {"id": "left", "name": "左轨迹", "frames": [
      {"time": 0, "x": 0.18, "alpha": 1, "ease": "linear"},
      {"time": 4, "x": 0.28, "alpha": 0.4, "ease": "smooth"}
    ]},
    {"id": "right", "name": "右轨迹", "frames": [
      {"time": 0, "x": 0.82, "alpha": 1, "ease": "linear"}
    ]}
  ],
  "notes": [
    {"id": 0, "type": "tap", "time": 3, "line": "left", "duration": 0},
    {"id": 1, "type": "hold", "time": 5, "line": "right", "duration": 1.5}
  ]
}
```

## 时间与坐标

- `time` 为音符头部到达判定线的谱面时间；Hold 尾部到线时间为 `time + duration`。
- `offset` 为谱面整体相对音乐的延后秒数，正值使音符更晚到线。运行时时间为 `音频时间 - 谱面 offset - 用户补偿秒数`。
- `bpm` 是元数据。运行时按秒判定，允许离线转换不同 BPM 的谱面。
- `editor` 是桌面编辑器的网格元数据，游戏忽略它。`meter` 为每小节拍数，`division` 为细分分母，`gridUnit` 为 `beat`（每拍）或 `bar`（每小节）。
- `approachTime` 为谱面建议下落时长元数据；当前运行时使用设置页保存的值，默认 2.2 秒。
- 逻辑画布高度为 600，宽度在 800（4:3）至 1066.667（16:9）之间。
- `x=0..1` 映射到左右各保留 48 个逻辑像素后的游戏场地。`y=0..1` 映射到整个逻辑画布高度，从上向下增加。
- 固定判定线位于 `y=0.8`。音符不具有点击用的 y 坐标，触控只受当前区域 y 范围限制。暂停按钮占用的触点优先作为 UI 操作。
- 区域边界在 HUD 外可见，判定仍依据完整区域坐标。超宽屏外侧留白不属于场地。

## v3 轨迹与音符绑定

游戏 0.6.0 与制谱器 0.7.0 使用 v3。`lines` 包含 1–64 条轨迹：`id` 必须唯一，1–64 个 ASCII 字母、数字、下划线或连字符；`name` 用于编辑显示；`frames` 为 1–256 个严格递增的关键帧。每帧字段为绝对秒数 `time`、横向位置 `x`、线透明度 `alpha`、过渡 `ease`。时间非负且折算拍数不超过 600000，位置和透明度为 0–1；过渡与区域共用 `linear/smooth/hold`。

音符不再保存 `x`，只通过 `line` 引用轨迹。`type/id` 是类型和编辑标识，`time` 为判定时间，Hold 的 `duration` 必须大于 0。无效引用或重复轨迹 ID 会拒绝加载。旧 v1/v2 的音符 `x` 自动转换成共享静止轨迹；新导出文件统一为 v3，不能在 0.4.0 及以前的游戏中运行。

设当前谱面时间为 `t`，路径上的一点预计在 `s` 到达判定线，轨迹关键帧插值为 `X(t)`：

```text
路径横坐标 = X(s)
路径纵坐标 = 480 - (s - t) × (480 - 105) / approachTime
```

同一个绝对时间 `s` 的横坐标始终固定，当前时间 `t` 只改变它的纵坐标。因此线、Tap 和弯折的 Hold 均竖直下落，折点也随谱面向下经过判定线。Tap 取 `s = note.time`；Hold 沿起止时间之间的多个 `s` 绘成带状多边形，头部、中段、尾部可处于不同横向位置，各段下落时不横移。采样包含关键帧对应的精确拐点及保持过渡的跳变边界。进行中的 Hold 从 `max(note.time,t)` 开始裁切绘制。编辑器用拍单位执行同一公式；时间轴缩放只改变纵向像素间距。

`alpha(t)` 只控制整条轨迹和下方交点的显示，音符保持可见；透明度不改变判定。Tap 和尚未按下的 Hold 头按自身起始时间的 `X(note.time)` 判定，容差窗口内位置不漂移。正在按住的 Hold 使用当前裁切点 `X(clamp(t,note.time,note.end))`，手指需随下方交点移动；高度仍只受当前二维判定区域限制。暂停时所有轨迹与区域共用冻结时钟。

0.5.0 的 v3 文件可直接载入并采用本节新行为，无需改写音符数据。旧版游戏虽能解析 v3，但仍使用旧的路径运动算法；检查本节效果应使用 0.6.0 或更新的游戏。

## 区域段落

`sections` 必须连续、无重叠，每段时间范围为 `[start, end)`。建议最后一段延伸到音乐结束后几秒，覆盖补偿设置。当前时间没有对应段落时，所有点击均被禁用。

每个 `rects` 元素是 `[left, top, right, bottom]`，必须满足 `0 ≤ left < right ≤ 1` 与 `0 ≤ top < bottom ≤ 1`。同一段多个矩形取并集，边界包含在区域中。`rects: []` 表示全屏禁止判定。

区域可以离开判定线，比如只开放上半屏：玩家在上半屏按音符的横向位置点击，仍以音符抵达下方固定线的时刻进行判定。

## v2 区域移动与旋转

从游戏 0.4.0 开始支持 `version: 2`。静态谱面仍可用 v1；带区域关键帧的谱面必须为 v2 或 v3，旧版游戏会拒绝加载，避免把运动区域误当作静态区域。

在段落中添加 `motions`，与 `rects` 一一对应，每个元素为该矩形的关键帧数组。整个 `motions` 可省略或为 `[]`，单个矩形的空数组表示静态。

```json
{
  "start": 0, "end": 10, "label": "平移与旋转",
  "rects": [[0.15, 0.3, 0.85, 0.65]],
  "motions": [[
    {"time": 0, "x": 0, "y": 0, "angle": 0, "ease": "smooth"},
    {"time": 4, "x": 0.05, "y": 0.15, "angle": 45, "ease": "linear"}
  ]]
}
```

- `time` 是整首谱面的绝对秒数，与音符使用同一时钟；编辑器存储绝对拍数，导出时按 BPM 转换。裁切区域段落不会重新计时。
- `x/y` 是相对原始矩形中心的位移，范围为 ±2，正 X 向右、正 Y 向下。基础矩形仍遵守 0–1 坐标要求，移动/旋转后可超出画面，屏幕外不可判定。
- `angle` 为绕自身中心旋转的角度，正值顺时针，范围 ±36000。按原始角度差插值，不自动取最短路径，因此 0 → 360 表示一整圈。
- `ease` 作用于本帧到下一帧：`linear` 线性、`smooth` 使用 `u²(3−2u)`、`hold` 保持到下一帧时瞬移；省略时为 `linear`。首帧前、末帧后保持该帧的位移和角度。
- 每个矩形最多 256 帧，时间严格递增且非负；全谱最多 20000 帧。编辑器拍数上限 600000，游戏以 `time × BPM / 60` 验证相同上限。

旋转使用实际场地宽高比 `A = (逻辑宽度 − 96) / 600`。先绕原始矩形中心旋转，再叠加位移。对局部坐标 `(dx,dy)`，旋转后为 `(cosθ·dx − sinθ·dy/A, sinθ·dx·A + cosθ·dy)`。游戏对触点执行逆变换后判断是否落在基础矩形内；渲染多边形与编辑预览使用相同公式，16:9 与 4:3 下都保持物理矩形形状。

多个运动矩形仍取并集。Hold 每次更新均以当前区域判定，暂停冻结动画时钟；自动演示会在音符所在的垂直列内寻找当前有效位置并跟随移动。导出检查对 16:9 和 4:3 验证音符头部可触及性，运动中的 Hold 仍需要在预览中检查完整路径。

## 判定规则

1. 触点必须在当前有效矩形中。
2. 触点 x 与音符所绑轨迹的实时 `X(t)` 的差值不超过场地宽度的 8.5%。
3. 从时间窗口内符合条件的待判音符中，选择绝对时间差最小者。一根手指的一次按下只判一个音符。

| 时间误差 | 判定 | 分值系数 |
| --- | --- | --- |
| ≤ 60ms | Perfect | 1.00 |
| ≤ 120ms | Good | 0.65 |
| ≤ 160ms | Miss | 0 |
| 超出 160ms | 不触发；超过迟判窗口自动 Miss | 0 |

Hold 头部需通过同样的按下判定，并绑定该 pointerId。过程中要求手指留在有效矩形中且保持横向对位，离开超过 85ms 即断连。尾部允许提前 80ms 松手；持续按到尾部也自动完成。整个 Hold 只计一个音符，分级取头部的判定结果；中途断连则整个音符为 Miss。

暂停冻结音乐与谱面并解绑手指。恢复倒数期间允许重新绑定进行中的 Hold，倒数结束后未接住会断连。系统触控取消会中断当前 Hold。

总分为 `round(1,000,000 × 已获得分值系数总和 / 音符总数)`；准确率为已完成音符的平均系数。Miss 清空连击。

## 制谱建议

- 所有音符在判定时应至少有一个有效矩形覆盖其 x。
- 新版示例的四条轨迹以 0.18 / 0.39 / 0.61 / 0.82 为初始位置，增加位置和透明度关键帧。
- 同列 Hold 期间不要安排额外音符；区域收缩时不要让 Hold 无预告地变成不可保持。
- 建议保留至少 2 秒开场准备时间，最多双指重叠，避免谱面结束晚于音频结束。
- 修改谱面后运行 `test.ps1`。整曲模拟中的预期音符数需随谱面更新。

## 便携谱面包

0.2.0 支持 `.interval` 文件，实际为 ZIP，必须包含 `chart.json` 和 `audio` 字段引用的歌曲文件。桌面编辑器将歌曲统一命名为 `music.ogg` / `music.mp3` 等安全文件名，不保留目录。游戏通过系统文件选择器导入并复制至内部存储。

导入器限制 JSON 为 4 MB、歌曲为 256 MB、音符数为 20,000，验证有限数值、时长、连续区域和文件路径，并拒绝路径穿越或重复 ZIP 文件名。
