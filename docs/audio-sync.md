# 0.9.1 制谱器试听 / 0.8.1 Android 流速

制谱器原实现没有等待上一段声音播放结束，但通过界面定时器逐个启动独立 QSoundEffect 实例。多个实例启动和音乐位置通知不共用采样时钟，因此双押和密集音符存在相对抖动的可能。原测试只核对触发数量，无法证明出声间隔。

现在歌曲、Tap / Hold 头音效、节拍器先按 48kHz PCM 的采样点混合，再由同一个 QMediaPlayer 播放。双押的起始采样编号相同；相隔 10ms 的两次声音相隔 480 个采样。音效可以重叠，Hold 尾不重复发声。过大的混合峰值以软限幅处理，不移动声音起点。界面定时器只更新统计，不触发实际声音。

解码与混合在后台进行，结果缓存在本机 `pcm-preview`，保留最近六条混合音轨。音符时间、BPM、偏移、打击音量/开关、节拍器变化后重新生成；播放中修改会暂停，生成完成后从原位置继续。预览下落流速与歌曲播放倍率均无需重建；倍率会同时作用于歌曲和音效。原始歌曲、工程音频路径及导出歌曲不被替换。底部音量保持 0–200%，默认 150%。

Android 的打击音使用预加载 SoundPool，最多 12 声部，没有等待前一声结束的逻辑。本次保留该播放方案。APK 的下落时间可调范围由 1.2–4.0 秒扩展为 **0.6–4.0 秒**，每次 0.2 秒。数字越小下落越快；已有设置不会自动变为最快。

验证范围：

- PCM 内容测试检查同点双押叠加、10ms / 20ms 密集音重叠、解码缓冲边界处音乐与音效的同点对齐、负偏移、静音、音量、尾部裁剪及限幅。测试读取实际采样数据。
- 真实 Qt 播放器检查混合 WAV、暂停继续、跳转、循环、音效开关和音量重建、0.5 / 0.75 / 1 倍播放、节拍器。
- Android 在 16:9 和 4:3 下通过设置按钮调整至 0.6 秒并验证下限、步长、持久化和游戏运行。

本次实测结果：49 个 Python 单元测试、8 组 Qt 界面回归通过；打包后的 EXE 可解码并播放内置 Ogg，Qoder 模型与遮罩 Key 默认填充正常。Android 16:9 / 4:3 各 16 项运行检查通过，游戏核心判定、区域运动、轨迹及全曲模拟回归通过。另测 44.1kHz 单声道歌曲的 Qt 解码转换、加载期间切换歌曲与取消待播放请求。

采样对齐消除的是歌曲与预制打击音之间的相对调度偏移；本机声卡、扬声器或蓝牙设备的整体输出延迟仍由系统决定。
