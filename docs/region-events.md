# 区域四栏与批量编辑 · Composer 0.11.0

运行 `dist/editor-0.11.0/IntervalComposer/IntervalComposer.exe`，保留整个目录。配套游戏为 `dist/Interval-0.10.0.apk`。原工程、歌曲转换缓存和 API 配置继续沿用。

## 区域时间条

在主界面「判定区域」选中段落和矩形，点击「区域 / 四栏编辑」。四栏共用音乐小节网格、固定下方判定线和播放游标：

| 栏目 | 起止值 | 含义 |
| --- | --- | --- |
| 中心点位置 | `[X,Y]`，各 -2～3 | 绝对中心点，X 向右、Y 向下；0～1 为游戏区域内，允许从画面外进入 |
| 旋转角度 | -36000～36000 度 | 绕当前中心顺时针旋转 |
| 总长 | 0.001～4 | 旋转前的横向尺寸，以游戏区域宽度为 1 |
| 总宽 | 0.001～4 | 旋转前的纵向尺寸，以游戏区域高度为 1 |

拖出长条确定起止拍，右侧填写起止值和变化类型，再点「应用选中长条」。支持直线、Sin 缓入缓出 / 缓入 / 缓出、平滑 S 型、保持到末端切换。拖中部移动时间，拖端点改变范围；同栏不允许重叠，不同栏独立。

首条前保持初始值，条与条之间保持上一终值。原静态矩形及旧移动/旋转关键帧自动映射为初值和可编辑长条；未修改的旧通道保持原效果。区域只在主界面该段的起止时间内生效，其他段保持原状。对话框「确定」返回区域草稿，再点主界面「应用时间段」写入工程；取消不修改工程。

## 框选与粘贴

- 主音符页面、线四栏、区域四栏：按住 **Ctrl 拖动**框选。主音符页面保留旧 Shift 框选方式，框选可直接覆盖当前 Tap/Hold 放置工具。
- 在画布上 **Ctrl+C** 复制，**Delete** 批量删除，**Ctrl+V** 粘贴；线页面允许同时框选绑定音符和多栏时间条。可整体撤销/重做。
- 粘贴将全部内容的**最早音符头 / 时间条起点**对齐当前判定线的拍数，保持相对间距、Hold 长度及曲线参数，粘贴时不再次吸附网格。
- 同类页面之间可复制；线页面的音符粘贴后绑定当前选中线，主音符页面粘贴保留原绑定。区域和线的不同类型时间条不能混贴。
- 遇到同线同拍音符、同栏时间条重叠或超出谱面时，本次粘贴整体拒绝，并显示原因。
- 数字框里的 Ctrl+C/V 保持普通文字操作。数字显示精度不会在仅打开并确定对话框时改变原始时间。

## 滚轮

三个编辑画布中，一个滚轮刻度固定移动当前网格的一格。每拍 1/6 时移动 1/6 拍；4 拍一小节、每小节 1/6 时移动 2/3 拍。向上前进，向下回退。高精度滚轮累积到一个刻度再移动；仅提供像素滚动的触控板以累计 40 像素作为一步。Ctrl＋滚轮仍用于缩放。

## Agent

原有 `set_track` 已支持新增线、位置和透明度关键帧。本版补齐：

- `set_track_events(line_id, channel, events)`：`channel` 为 `x`、`alpha` 或 `speed`；起止值范围分别 0～1、0～1、0～8。替换该栏完整时间条，保留其他栏和绑定音符。
- `delete_track(line_id)`：只能删除无音符绑定的线，至少保留一条。
- `set_region_center(region_index, rect_index, events)`：中心点 from/to 为 `[X,Y]`。
- `set_region_events(region_index, rect_index, channel, events)`：channel 为 `angle`、`width`、`height`。

以上时间条为 `{start,end,from,to,ease}`，时间全部为绝对拍数，从 0 开始；第 N 小节开头为 `(N-1)*meter`。每栏最多 256 条。`events=[]` 表示固定该栏初始值；修改前先读取 `get_track` / `get_region`，保留该栏不在请求范围的内容。完整声明与示例在 `editor/skills/interval-chart-agent/references/`。工具仍只改待预览草稿，由用户在 Agent 面板应用。

## 文件格式与 Android

含区域时间条的工程和谱面为 **v5**，需要本版 Android 0.10.0。没有区域时间条的谱面仍按 v3/v4 导出；v1～v4 继续可读。区域 `events` 数组与 `rects` 一一对应，各对象按 `center/angle/width/height` 保存独立事件列表。缺失的通道沿用原矩形/旧 motions。工程时间用拍；Android JSON 的 start/end 用秒，offset 规则不变。游戏的渲染、点击判定和 Hold 连续判定共同使用变化后的矩形。

```json
{
  "events": [{
    "center": [{"start": 4, "end": 12, "from": [0.25, 0.75], "to": [0.25, 0.25], "ease": "sine_in_out"}],
    "angle": [{"start": 4, "end": 12, "from": 0, "to": 90, "ease": "linear"}],
    "width": [{"start": 4, "end": 12, "from": 0.4, "to": 0.6, "ease": "smooth"}],
    "height": [{"start": 4, "end": 12, "from": 0.3, "to": 0.2, "ease": "linear"}]
  }]
}
```

上例用于工程时，4～12 表示拍；用于导出 JSON 时，4～12 表示秒。

## 验证

`editor/tests/smoke_batch_regions.py` 验证真实 Qt 框选/键盘操作、四栏创建、混合批量粘贴、冲突原子性、撤销及全部细分网格，输出 `docs/region-batch-tests.json`。单元测试覆盖旧帧迁移、独立曲线、尺寸判定、v5 往返、BPM 换算和 Agent 原子编辑。Android `RegionEventsSmoke` 使用桌面实际导出的包，比较两种画幅的顶点、点击与自动触及点，并验证原生播放、暂停和 Hold 恢复。
